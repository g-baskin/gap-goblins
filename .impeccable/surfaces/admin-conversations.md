# Surface Brief: `/admin/conversations`

- **Mode:** Operate
- **Job:** Let an authenticated operator triage contact conversations, understand a single cross-channel history, and prepare the next safe response without leaving the workspace.
- **Proof sequence:** Inbox state and ownership → contact and active channels → canonical chronology → CRM context and next commitment → channel-aware composer state.
- **Chosen direction:** "Contact signal desk" — a calm, product-owned operating surface built from the existing blue/slate system, where one chronological spine connects communication and CRM facts.
- **Seed key:** unavailable (the installed Stinger does not include `concept-seed.mjs`)
- **Anti-references:** No provider-console chrome, no Chatwoot/GoHighLevel imitation, no channel-specific silos, no fake live-send success, no decorative dashboard card grid.

## Direction Contract

- **THESIS:** One contact, one accountable chronology; refuse the category default of separate channel inboxes.
- **OWN-WORLD:** Existing blue/slate tokens, crisp divided work areas, compact channel glyphs, restrained status color, and a readable event spine.
- **STORY:** The operator sees what needs attention, confirms the full relationship context, and prepares the right channel response.
- **FIRST VIEWPORT:** Queue at left, active chronology in the center, CRM context at right; reply controls stay attached to the chronology.
- **FORM:** A responsive three-region signal desk that collapses to queue → conversation → context on narrow screens.
